Is the contrastive objective what helps?

Every arm above compares an adapted backbone against an unadapted one, which confounds the image/report objective with domain adaptation of DINOv2 to knee MRI at all. The control separates them: identical cohort, depth, learning rate, schedule and seed, with only the image/report correspondence destroyed.

The control is valid. Validation pairings were left intact, and validation Recall@1 collapsed to 0.0011 against a 0.0023 chance baseline while validation loss rose monotonically from 6.09 to 8.40. It learned no alignment, which is what the control requires.

Both mechanisms are real; the objective is the larger half. Across three permutation seeds the true pairing wins every time, by +0.0311 to +0.0538, and two of the three intervals exclude zero. So the image/report objective does contribute beyond mere adaptation. But the control still recovers a substantial part of the gain without any correct pairing, so “contrastive learning improves label readout” overstates it: part of the effect is available from adapting the same blocks against a non-semantic target. Note also what the control did — its training loss fell from 3.47 to 1.41 while validation loss rose to 8.40, so it memorised the random pairings. That requires features which separate individual studies, which is closer to instance discrimination than to domain adaptation. These runs cannot tell those two apart; an images-only self-supervised arm would.

How the AUC is produced

The AUC is not read off a trained classifier head. Every contrastive model is frozen, features are extracted once, and a fresh linear probe is cross-validated on top. Nothing in the scoring path has gradients, and no pathology label ever reaches the contrastive training.

From pixels to a number

  1. Input. Three MRI planes × three slices each, 224×224, cropped to 130 mm, slices drawn from the 0.2–0.8 depth band, normalised with ImageNet statistics. Three slices per plane is fixed by the backbone’s three input channels, not chosen.
  2. Backbone. facebook/dinov2-small at a pinned revision — hidden width 384, 12 transformer blocks. Each plane is encoded independently, then described by its CLS token concatenated with the mean of its patch tokens: 2 × 384 = 768 dims per plane. That is where the 768 in the feature names comes from.
  3. Pooling across the three planes — the three feature sets scored here:
    • uniform_mean_768 — a plain average over planes. Every headline number on this page uses this one, because it is the only pooling with no learned parameters, so two arms differ solely by their backbone weights.
    • plane_attention_768 — the tower’s own learned pooling: add a per-plane embedding, then LayerNorm → Linear(768→384) → Tanh → Linear(384→1), softmax over the three planes, weighted sum.
    • projection_256 — the contrastive projection head: LayerNorm → Linear(768→256) → GELU → Linear(256→256), L2 normalised.
  4. The probe. Per label, an L2 logistic regression on the frozen features, fitted inside stratified folds. This is the entire “head” — a linear decision function, so the AUC measures how linearly separable the labels already are in the frozen representation.
  5. The metric. Each study gets exactly one held-out score per label; those pooled out-of-fold scores give midrank AUROC and average-precision AUPRC, macro-averaged over the 12 labels. The point estimate comes from scikit-learn; the bootstrap uses a rank-sum equivalent, and the script asserts the two agree to 1e-9 on real scores before building any interval.

Every value above is fixed in the probe config before the first fit. None of it was tuned on these 56 studies, which is what keeps the comparison between arms honest — the probe is held constant so the representation is the only thing that varies.

Ways to improve further

Split deliberately: changes that would make the representation better, and changes that would only make the number bigger.

Likely real gains

  1. Separate depth from learning rate. All arms use --lr-image 1e-5, chosen when one block was trainable. The 4-block arm has four times the trainable surface at that same rate, so “depth helps” and “this rate suits more blocks” are confounded. An LR sweep at each depth is the highest-value next experiment, because depth is the only lever measured so far whose interval excludes zero.
  2. The depth ladder has already turned. 1 → 2 → 4 → 8 blocks gives 0.6695 → 0.6838 → 0.7105 → 0.7164, all seed-2026 levels on exposed gold studies (the 4-block level pools to 0.7106 across seeds, and is 0.6938 held out). The 8-block screen has run: +0.0062 over 4 blocks, an interval spanning zero, so 4 of 12 is at or near the useful optimum and there is nothing further to gain by climbing.
  3. A larger backbone. Gains scaling with trainable depth suggests capacity is binding. dinov2-base doubles the hidden width to 768 and fits in 8 GB at this batch size — depth costs memory but almost no time here (3.2 → 4.5 GB, 1,235 → 1,292 s).
  4. Drop the learned plane attention at readout — free, and already measured. On the same checkpoint, attention pooling scores 0.0185 below a uniform mean, while concatenating all three planes scores +0.0010, i.e. no information is lost by not pooling. The deficit is the re-weighting, not the representation. Exporting pre-attention plane features costs no training.
  5. Weak supervision from the reports. The full 4,407-study cohort has reports but no adjudicated labels; LM-extracted labels already exist in data/lm_label/. An auxiliary multi-label loss over that cohort is the largest untapped headroom — but any study in the gold set must be excluded from it, or the evaluation is contaminated.

Changes that would only move the number

  1. Tuning the probe on these studies. Sweeping C, enabling class_weight='balanced' for the rare labels, or changing the fold count would almost certainly raise the macro AUROC — by selecting on the evaluation set. If ever done, it produces a development estimate and must be labelled one.
  2. A non-linear probe head. An MLP would measure probe capacity, not representation quality, and 56 studies with 8–33 positives per label cannot support fitting one.
  3. Reading projection_256 as a result. It is a learned 768→256 compression; a linear probe cannot gain information from compression, so it is reported but is not evidence about the representation.

The binding constraint is not the model

With 56 studies and 8–33 positives per label, bootstrap intervals on a single arm run roughly ±0.015 to ±0.03 macro AUROC. Improvements smaller than the 0.0038 seed spread cannot be detected here at all. More independently adjudicated labels would do more for establishing a gain than any architecture change — and, unlike everything above, would also make a generalisation claim possible, which no rerun on these studies ever can.
