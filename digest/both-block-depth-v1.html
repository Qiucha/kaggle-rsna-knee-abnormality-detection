LoRA GPU Memory Profiling & Parameter Efficiency Analysis

  • Memory Wall at 8 Blocks for BS=32: Backpropagation requires storing intermediate activations across all adapted blocks (~1,850 MiB per 2 blocks at BS=32). Consequently, 2, 4, and 6 blocks fit safely in 8 GB VRAM, while 8 blocks demands >8.8 GB and triggers OOM regardless of whether LoRA or Full FT is used.
  • Extreme Parameter Efficiency: At 6 blocks (the deepest viable depth at BS=32), LoRA reduces trainable parameter counts by 84% to 95% (Full FT: 54.01M params → LoRA r=16: 2.82M params [0.93%], r=32: 4.81M params [1.58%], r=64: 8.79M params [2.85%]).
  • Full-Depth Adaptation at BS=16: By adjusting batch size to 16, LoRA enables adapting all 12 transformer blocks across both towers within ~7,000–7,250 MiB peak reserved memory, fitting comfortably within the 8 GB budget with ~940–1,200 MiB headroom.

Feasibility Analysis: Preventing OOM via Activation/Gradient Offloading & Checkpointing

  • Root Cause of OOM: In multi-plane contrastive learning, each study carries 3 image planes (Sagittal, Coronal, Axial). At batch size 32, the image tower processes 96 forward passes per batch. The autograd forward pass must retain intermediate activations across all unfrozen blocks for backpropagation (~1,850 MiB per 2 blocks). At 8 unfrozen blocks, intermediate activations exceed 7.4 GB, inevitably exceeding the 8,192 MiB physical VRAM of the RTX 3070.
  • Feasibility of Moving Activations to Host RAM (save_on_cpu): Using torch.autograd.graph.save_on_cpu(pin_memory=True), PyTorch automatically intercepts intermediate activations produced during the forward pass and offloads them to pinned host memory (system RAM), streaming them back to GPU only when needed during the backward pass. This slashes peak reserved VRAM from 9,216 MiB → 2,416 MiB, freeing up a massive +5,775.5 MiB of headroom (6.8 GB saved)!
  • Gradient Checkpointing Synergy: Enabling gradient checkpointing (backbone.gradient_checkpointing_enable()) trades ~25% recompute for memory by discarding forward activations and recomputing them during backward. For 8-block Full FT, peak VRAM drops from 9,216 MiB → 3,282 MiB (+4,909 MiB headroom). For 12-block LoRA, peak VRAM is only 3,494 MiB (+4,697 MiB headroom), completely solving the memory wall and enabling full 12-block BS=32 training!

Overfitting Diagnosis & Combined Regularization Solutions (BS=64)

Root Cause: Numerical Temperature Artifact vs. Genuine Memorization

  • 1. Inverse Temperature Runaway (τ-1 = elogit_scale): In standard contrastive training, the learned logit scale was allowed to grow unbounded (reaching τ-1 ≈ 40–70, τ ≈ 0.014). In InfoNCE loss -log(exp(sii/τ) / ∑ exp(sij/τ)), dividing dot products by an ultra-small τ exponentiates slight cosine margin errors on the validation batch, creating an artificial loss explosion (e.g. from 3.39 → 4.26) even when the actual retrieval rankings (Recall@1) remain flat or improving!
  • 2. Hard Negative Penalty on Semantically Identical Patients: InfoNCE treats every other study in a batch as a strict negative (y=0). At batch size 64, many pairs of knee MRI scans share the exact same clinical findings (e.g., both have Medial Meniscus tear + ACL tear). Training forces representations of clinically identical knees apart, driving training loss down to 0.139 (memorization floor) and degrading downstream generalization on shared pathologies.
  • 3. LoRA Placement Clarification: LoRA adapters are applied to Full Transformer Block Linear Layers (both Self-Attention query, key, value, out AND Feed-Forward MLP fc1, fc2 in DINOv2; intermediate.dense, output.dense in Multilingual-E5) across all adapted blocks (36 linear layers per tower, 72 total). Study projection heads remain full-rank trainable layers. While low-rank (rank=64) greatly regularizes weight updates vs full fine-tuning, unconstrained adapters can still overfit report wording without explicit dropout and stochastic depth.

The 4 Synergistic Fixes Implemented

  • Fix 2 • Finding-Aware Soft-Target InfoNCE (--label-similarity-weight 0.1): Interpolated one-hot targets with pairwise cosine similarity matrices computed from 12 gold labels (via data/lm_label/lm_labels_kaggle.csv). Negative studies sharing similar findings are penalized gently rather than forced artificially apart.
  • Fix 3 • Dual Regularization (--lora-dropout 0.1 --image-drop-path-rate 0.05): Injected 10% dropout inside LoRA adapters and 5% stochastic depth (drop-path) restricted exclusively to adapted vision backbone transformer blocks to prevent co-adaptation.
  • Fix 4 • Clamped Inverse Temperature Scale (--max-inverse-temperature 16.0): Capped τ-1 ≤ 16.0 (τ ≥ 0.0625) at every optimizer step, preventing the exponential numerical distortion of validation loss.
  • Fix 5 • Step Count Parity (40 Epochs, 2,200 Steps): Doubled the epoch count from 20 to 40 so that batch size 64 executes the exact same number of optimizer updates (2,200 steps) as batch size 32.
